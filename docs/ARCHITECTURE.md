# SYNC — Архитектура MVP

> «Переводчик эмпатии» для пар. Не медицинский трекер, а инструмент коммуникации.
> Документ фиксирует решения, принятые с со-основателем. Версия 1.0 (01.08.2026).

---

## 0. Принципы (не нарушать)

1. **MVP для одного разработчика.** Минимум экранов, сущностей, серверной логики, инфраструктуры. Решение в 20 строк лучше решения в 500.
2. **Наша фича — коммуникация, не медицина.** Никаких предсказаний цикла, диагнозов и «научных» заявлений.
3. **Симметрия ценности, асимметрия механики.** Девушка (OWNER) настраивает «профиль заботы» и получает выгоду: партнёр перестаёт угадывать и доставать вопросами. Партнёр (PARTNER) получает ежедневную карточку-подсказку.
4. **Она — канал роста.** Ей бесплатно всегда. Скриншот-момент — фраза, не бейдж.
5. **Приватность как фича.** Данные цикла живут на её устройстве. На сервер уходит только «фаза». Режим инкогнито — в любой момент, без объяснения причин партнёру.
6. **Этика в промптах.** Ирония — только про ситуацию и действия партнёра, никогда про неё. Блоклист тем. Кнопка «не то» у обоих.

## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | **Next.js 16 (App Router)** | Фронт + API в одном процессе, один деплой, PWA из коробки |
| Язык | TypeScript (strict) | |
| Стили | TailwindCSS 4 | Опыт команды, glassmorphism-стиль из KatoCRM |
| БД | **SQLite (Prisma 7 + libsql adapter)** | Ноль инфраструктуры: один файл, WAL. Тысячи пар = десятки тысяч строк, SQLite справится. Переезд на Postgres = одна строка в prisma.config |
| Auth | **NextAuth 5 (Credentials + JWT)** | Email + пароль. trustHost: true, кастомный redirect callback (см. скилл mvp-web-app) |
| ИИ | **DeepSeek API** через интерфейс `generator` | Дешёвый, работает из РФ. Смена провайдера = 1 файл |
| Платежи | ЮKassa (RU) / интерфейс `payments` | Открытый вопрос: нужен ИП/самозанятость — см. §11 |
| PWA | manifest.json + sw.js (по скиллу mvp-web-app) | Ярлык на iPhone, TWA-обёртка для Google Play (тот же код) |
| Деплой | VPS + systemd + nginx + certbot | Один Next.js standalone-процесс. Docker — альтернатива, но не нужен при SQLite |
| Бэкап | cron: копия db-файла + uploads на сервер | Файл скопировал — бэкап готов |

**Платформы:** один веб-код → iPhone (ярлык PWA) + Android (TWA в Play Store). Нативный код не пишем.

## 3. Модель данных (ровно 4 сущности)

```prisma
// SQLite, WAL. enums: Role, Phase, Mood, Feedback, SubStatus

model User {
  id            String   @id @default(cuid())
  email         String   @unique
  passwordHash  String
  role          Role     @default(OWNER)   // OWNER = создательница профиля заботы; PARTNER = получатель подсказок
  careProfile   Json?    // её выборы: еда/пространство/слова (id карточек + свободное поле)
  phase         Phase?   // ТОЛЬКО фаза, без дат (обновляется с её устройства)
  phaseUpdatedAt DateTime?
  mood          Mood?    // последний check-in «как себя чувствуешь» (без истории)
  moodUpdatedAt DateTime?
  pausePartner  Boolean  @default(false)   // режим инкогнито: партнёр видит «паузу», без причин
  coupleId      String?
  couple        CoupleProfile? @relation(fields: [coupleId], references: [id])
  subStatus     SubStatus @default(NONE)   // NONE | TRIAL | ACTIVE
  subExpiresAt  DateTime?
  freeCardsUsed Int      @default(0)       // пейволл: 3 бесплатные карточки
  achievements  Achievement[]
  createdAt     DateTime @default(now())
}

model CoupleProfile {
  id         String   @id @default(cuid())
  inviteCode String   @unique              // 6 символов, без 0/O/1/I (напр. «K7XQ2M»)
  locale     String   @default("ru")       // ru | en — язык подсказок
  ownerId    String   @unique
  partnerId  String?  @unique
  startDate  DateTime @default(now())      // «вместе с первого цикла»
  users      User[]
}

model DailyPrompt {
  id       String   @id @default(cuid())
  coupleId String
  day      String                          // YYYY-MM-DD (локальный день пары)
  text     String                          // итоговая подсказка
  source   Source   @default(AI)           // AI | FALLBACK
  feedback Feedback?                        // GOOD | MISSED | BAD (ответ партнёра)
  createdAt DateTime @default(now())
  @@unique([coupleId, day])                // одна карточка в день на пару
}

model Achievement {
  id         String   @id @default(cuid())
  userId     String
  type       String   // ninja_7d | gentleman_10 | first_cycle_together
  unlockedAt DateTime @default(now())
}

enum Role    { OWNER PARTNER }
enum Phase   { MENSTRUAL FOLLICULAR OVULATION LUTEAL UNKNOWN }
enum Mood    { TERRIBLE MEH OKAY GREAT }
enum Feedback{ GOOD MISSED BAD }
enum Source  { AI FALLBACK }
enum SubStatus { NONE TRIAL ACTIVE }
```

**Почему так:**
- Дат цикла на сервере **нет вообще**. `phase` — производная величина, которую девушка явно разрешила передавать. Это юридическая и репутационная подушка.
- `careProfile` — Json, а не таблица: карточки выбора мы можем менять без миграций.
- `DailyPrompt.unique(coupleId, day)` — дешёвый кэш: одна генерация ИИ в день на пару.

## 4. Данные цикла на устройстве

- **Хранится на устройстве OWNER** (localStorage/IndexedDB): даты начала последних циклов, check-in'ы.
- **Расчёт фазы** (клиент, `lib/phase.ts`): день цикла = (сегодня − начало последнего) mod avg(28). Без «предсказаний» — только текущее окно. Всегда есть кнопка «не знаю / пропустить» → UNKNOWN.
- **На сервер уходит только:** `phase` + `mood` + время обновления. Точка.
- Check-in «как себя чувствуешь» — 4 эмоции одним тапом (TERRIBLE/MEH/OKAY/GREAT). Это эмоциональный контекст для подсказки, не медицинские данные.

## 5. API (минимальный набор)

| Метод | Путь | Кто | Тело / Ответ |
|---|---|---|---|
| POST | /api/auth/... | все | NextAuth (credentials) |
| POST | /api/pair | OWNER | → { inviteCode } |
| POST | /api/pair/join | PARTNER | { inviteCode } → пара создана |
| GET | /api/prompt/today | PARTNER | → карточка дня (генерация при первом запросе за день, далее из кэша) |
| POST | /api/prompt/feedback | PARTNER | { promptId, feedback } |
| PUT | /api/profile/care | OWNER | { careProfile } |
| PUT | /api/profile/phase | OWNER | { phase, mood } (с устройства, по явному согласию) |
| PUT | /api/profile/pause | OWNER | { pausePartner: bool } — инкогнито |
| DELETE | /api/profile | OWNER | удалить аккаунт и все данные |
| POST | /api/subscription/create | PARTNER | → платёжная ссылка ЮKassa |
| POST | /api/webhooks/yookassa | — | подтверждение платежа |

**Логика карточки дня (server action / route):**
1. Есть DailyPrompt на сегодня → отдать.
2. Нет → собрать контекст (фаза, настроение, careProfile, locale, счётчик дней вместе, feedback за 3 последних дня).
3. `generator.generate(ctx)` → текст. Провал/блоклист → `fallback` → текст. Сохранить в DailyPrompt (source=AI|FALLBACK).
4. Если `pausePartner` → вместо карточки отдаём нейтральное «она взяла паузу» (без причин, без дат).

**Пейволл:** PARTNER с `freeCardsUsed >= 3` и `subStatus != ACTIVE` получает карточку-заглушку с оффером. `freeCardsUsed` инкрементится при каждой выданной карточке.

## 6. AI-генерация (сердце продукта)

### Интерфейс (lib/ai/generator.ts)
```ts
interface PromptContext {
  phase: Phase; mood?: Mood; careProfile?: CareProfile;
  locale: "ru" | "en"; dayTogether: number;
  recentFeedback: Feedback[]; // за 3 дня
}
// generate(ctx) → { text, source }
```

### Системный промпт (RU; EN — аналогичный)
```
Ты — «переводчик эмпатии» в приложении для пар. Ты помогаешь партнёру
сегодня поддержать свою девушку: коротко, конкретно, с лёгкой иронией.

КОНТЕКСТ (JSON): фаза цикла, её настроение, её личный «профиль заботы».

ПРАВИЛА:
1. Одна подсказка, 1–2 предложения, заканчивается ОДНИМ конкретным действием на сегодня.
2. Ирония — только про ситуацию или про действия партнёра. НИКОГДА про неё:
   никаких шуток про её эмоции, вес, внешность, «гормоны», «истерики», сравнений с другими.
3. Запрещено: медицинские советы и диагнозы; «просто потерпи»; обесценивание её чувств;
   газлайтинг; упоминание, что совет сгенерирован ИИ.
4. Если она указала предпочтения (еда/пространство/слова) — опирайся на них.
   Если настроение TERRIBLE — меньше слов, больше действий.
5. Тон — заботливый друг, не инструкция и не приказ.
6. Пиши на языке пары (ru/en).
```

### Guard-слой (lib/ai/guard.ts)
- **Блоклист** (до генерации и после): вес, диета, истерик*, гормон* (в уничижительном контексте), потерпи, успокойся, придумай себе занятие, все женщины, твоя девушка должна…
- **Постфильтр:** содержит блок-слово → регенерация со строгим промптом (1 повтор) → фолбэк.
- **Фолбэк-библиотека** (`fallback.ts`): ~100 курируемых фраз по фазам × типам профиля × настроению, написанных вручную. Это наш «голос бренда» — и страховка от пустых экранов при сбое API.
- **Кнопка «не то»** у обоих: feedback BAD → контекст для следующих генераций (recentFeedback), и датасет для улучшения промптов.

### Стоимость
1 генерация на пару в день + регенерации. DeepSeek — доли копейки за запрос. Кэш в DailyPrompt.

## 7. Потоки (4 экрана)

**А. Онбординг OWNER (девушка):**
1. Регистрация (email + пароль) → «Создать пару» → инвайт-код.
2. Профиль заботы: 3 группы карточек-выборов (что помогает: **еда** — борщ/шоколад/тишина…; **пространство** — обнять/не трогать/побыть рядом; **слова** — «ты справишься»/«я рядом»/комплимент) + свободное поле. 1 минута.
3. Check-in фазы: «когда начался последний цикл? / не знаю» + «как себя чувствуешь?» — 2 тапа. Данные остаются на устройстве.
4. Экран приглашения: «Отправь ему ссылку — это спасет твою жизнь» + кнопка шеринга. **Виральная петля №1.**

**Б. Онбординг PARTNER (парень):**
1. По ссылке → регистрация → ввод кода (или код уже в ссылке).
2. Сразу карточка дня + объяснение «почему это работает» (1 экран, без воды).

**В. Карточка дня (ежедневный ритуал, как Duolingo):**
- Утром: «Сегодня ей нужно: тишина и борщ. Твоя задача — тишина. Борщ — по желанию.»
- Кнопки: **сделал ✅ / не то 👎 / пропустил**.
- Стреак: «🔥 5 дней подряд».
- Кнопка «поделиться» → брендированная PNG-карточка (canvas на клиенте, без бэкенда). **Виральная петля №2 — скриншот-момент.**

**Г. Настройки:**
- OWNER: режим инкогнито (пауза) — toggle; «удалить все мои данные» (hard delete); что видит партнёр (прозрачность).
- PARTNER: подписка, ачивки (приватные), отвязать пару.

## 8. Монетизация

- **OWNER — бесплатно всегда** (канал роста, не трогаем).
- **PARTNER:** 3 бесплатные карточки → пейволл. Подписка **249 ₽/мес или 1 490 ₽/год** (годовой — сильнее для кэша и удержания).
- Реализация: ЮKassa recurring (создание платежа → вебхук → ACTIVE + subExpiresAt). Интерфейс `payments.ts` — чтобы позже добавить Stripe для EN-рынка без переписывания.
- **Гипотеза проверяется:** конверсия free→paid и отток после пейволла. Всё остальное (голос, доставка еды) — только после подтверждения.

## 9. Геймификация (минимум, приватно)

| Ачивка | Условие | Видимость |
|---|---|---|
| Ниндзя эмпатии | 7 дней карточек без BAD | только ему |
| Джентльмен | 10 × GOOD | только ему |
| Первый цикл вместе | 28 дней пары | обоим (совместный, редкий) |

Совместная ачивка — единственное, что видно ей. Забота не превращается в «прохождение квеста» на её экране.

## 10. Приватность и этика (проверка перед каждым релизом)

- [ ] Никаких дат цикла на сервере. Только phase+mood с явного согласия.
- [ ] Инкогнито: мгновенная пауза, партнёр видит нейтральное «пауза» без причин и дат.
- [ ] Hard delete всех данных по кнопке (и в настройках, и по запросу на почту).
- [ ] Промпт-аудит: прогон 20 «стрессовых» сценариев перед релизом (см. §6, блоклист).
- [ ] Никаких утверждений «медицински подтверждено», «предсказание цикла». В UI — «похоже, сегодня…», не «диагноз».
- [ ] Никаких пушей/уведомлений, которые раскрывают цикл третьим лицам (пост-MVP, Telegram-бот — только с согласия OWNER).

## 11. Открытые вопросы (решаем до кода фазы 5)

1. **Платёжка в РФ:** ЮKassa/Робокасса требуют ИП/ООО. Lava / Продамус работают с самозанятыми. Пока не решили — пейволл можно включить «на выключателе» (env-флаг), не блокируя фазы 1–4.
2. **Домен:** нужен короткий, эмоциональный, свободный. Кандидаты: sync.love, empathia.app, ponimay.app… (проверить занятость). Без домена нельзя PWA/TWA.
3. **Рынок:** RU-first подтверждён. EN-слой (i18n + промпты) закладываем с первого дня, но не полируем.

## 12. Дорожная карта

| Фаза | Содержимое | Критерий готовности |
|---|---|---|
| 1 | Скелет: Next.js + Prisma + NextAuth + PWA, деплой на VPS, лендинг | Открывается по домену, регистрация работает |
| 2 | Пара (код), онбординг OWNER, профиль заботы, фаза на устройстве | Она проходит онбординг и отправляет ссылку |
| 3 | Карточка дня на фолбэк-фразах + фидбек + стреак | Парень получает карточку, отвечает |
| 4 | ИИ-генерация + guard-слой + «не то» | Подсказки персонализированы, блоклист работает |
| 5 | Пейволл + ЮKassa (если решён вопрос платёжки) | Оплата → ACTIVE |
| 6 | Ачивки, шеринг-PNG, инкогнито, полировка, TWA → Play, инструкция для iPhone | Готово к первому виральному запуску |

**Каждая фаза деплоится один раз, по нашему процессу: отчёт → «приступай» → код → финальный деплой.**
